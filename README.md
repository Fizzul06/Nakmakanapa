# Nak Makan Apa?

An Android app that decides where you should eat. Built for the **Mini AI Hackathon** under the theme **AI for Problem Solving**.

Existing food apps give you more options. This one narrows the choice to a single answer, checks that the answer is valid right now, and explains why.

---

## What it does

- **Surprise Me** — one tap gives you a restaurant, with a written reason generated by DeepSeek
- **Trendy Categories** — Mamak, Nasi Lemak, Fast Food, Cafes and more, each backed by a live Google search
- **Budget / Distance / Fancy filters** — each issues its own Google query rather than filtering a limited list
- **Search** — free-text search submitted to Google, with a session cache so repeat searches cost nothing
- **Adventure** — scenic route destinations
- **Saved** — bookmark restaurants, stored locally
- **Detail screen** — 3-photo swipeable gallery, live opening hours, AI review summary, and one-tap navigation

## How it works

Two AI services, each doing what it is good at.

| Service | Responsibility |
|---|---|
| **Google Places API (New)** | Every fact: name, address, coordinates, rating, review count, price level, opening status, photos |
| **DeepSeek API** | Language only: explanations, review summaries, intent parsing |

The guiding rule is **use AI for language, use verified services for facts.** A language model allowed to supply restaurant data will invent it convincingly, and a food app cannot afford that. Restaurant selection is done in code with a weighted random draw; DeepSeek writes the reason for a place already chosen.

## Setup

### 1. Get the keys

**Google Places API**
1. Open [Google Cloud Console](https://console.cloud.google.com/)
2. Create a project
3. Go to **APIs & Services → Library**, search for **Places API (New)**, and enable it
4. Go to **APIs & Services → Credentials → Create Credentials → API key**
5. Copy the key

> The legacy Places API is permanently retired and will return `REQUEST_DENIED`. You must use Places API (New).

**DeepSeek API**
1. Sign in at [platform.deepseek.com](https://platform.deepseek.com/)
2. Go to **API Keys → Create new API key**
3. Copy the key

### 2. Configure the project

```bash
cp local.properties.example local.properties
```

Then edit `local.properties`:

```properties
sdk.dir=/path/to/Android/Sdk
MAPS_API_KEY=your_google_places_api_key_here
DEEPSEEK_API_KEY=your_deepseek_api_key_here
```

`local.properties` is gitignored and must never be committed.

### 3. Build and run

```bash
./gradlew assembleDebug
```

Or open the project in Android Studio and press Run.

### 4. Set the emulator location

The Android emulator defaults to California, which returns American restaurants. Set it to Malaysia first:

**Extended Controls (`...`) → Location → search "Kuala Lumpur" → Save**

Or use the in-app location picker on the main menu.

## Tech stack

| Layer | Technology |
|---|---|
| Language | Kotlin |
| UI | Jetpack Compose + Material 3 |
| AI | DeepSeek `deepseek-chat` |
| Data | Google Places API (New) |
| Images | Coil with shared memory + disk cache |
| Local storage | DataStore Preferences |
| Location | FusedLocationProviderClient + Haversine distance |
| Networking | OkHttp + Gson |
| Min SDK | Android 12 (API 31) |

## Notes on API cost

Place Photos are billed **per photo**. The app was built with this in mind:

- 10 results per search, not 20
- Thumbnails at 400px, not 800px
- Shared image cache means revisiting a screen costs **zero** new requests
- Search fires on submit, not on every keystroke — typing costs nothing
- Repeat searches are served from an in-memory session cache
